# AI Signals

Виджет показывает сигналы API и подробный анализ. Внутренние компоненты не экспортируются в другие виджеты; metadata и registry нужны только для `AiSignalsWidget`.

## Представление данных

- `AiSignalsService` владеет загрузкой и HTTP-ошибками. DTO описаны в `services/ai-signals-service.types.ts`.
- `AiSignalsViewModelHelper`, `FundamentalViewModelHelper` и `TechnicalAnalysisViewModelHelper` преобразуют ответ API в типизированные модели представления. Отсутствующие и некорректные данные не подменяются нулём.
- Биржа берётся только из `signals[].exchange`, без значения по умолчанию и разбора `full_ticker`. Если API не предоставил биржу, анализ остаётся доступен, но запрос котировки, выбор инструмента для других виджетов и открытие заявки не выполняются.
- `SignalDetailsDialog` управляет раскрытием подробностей и открытием существующего диалога заявки. Прокруткой владеет тело модального окна, а не вложенные секции.
- `SignalDetailsService` получает последнюю цену через существующий `QuotesService` при открытии диалога и каждые 60 секунд. Закрытие, смена сигнала и уничтожение диалога отменяют предыдущие запросы и таймер. Цена обновляется в торговых планах консенсуса, аналитиков и сравнении; до первого успешного запроса используется цена сигнала, при ошибках — последняя корректная цена. Исторические данные технического анализа и прибыль от цены входа не меняются.
- `SignalSummary` одинаково показывает консенсус и мнение аналитика: направление, действие, уверенность, срок, обоснование, торговый план и риски. Риски отображаются после торгового плана, если есть хотя бы один уровень риска или причина воздержаться.
- `SignalSummaryViewHelper` задаёт общие правила видимости для диалога, консенсуса и аналитиков. Срок показывается только вместе с известной прибылью; сам по себе он не создаёт пустую панель. Сводка только с рисками остаётся видимой.
- При обновлении текущей цены сохраняются ссылки на неизменившиеся данные фундаментального и технического анализа, чтобы не пересоздавать их графики и таблицы каждую минуту.
- `SignalAnalysisDetails` объединяет новости, фундаментальный и технический анализ, мнения аналитиков. Необязательные блоки скрываются, если данных нет.

Список сортируется по убыванию `confidence`; отсутствующая уверенность располагается в конце, при равенстве сохраняется порядок выбранных тикеров. В карточке показываются тикер с иконкой, дата прогноза, направление, ожидаемая прибыль со сроком и круговой индикатор уверенности.

Повторяющиеся тикеры в сохранённом списке объединяются после нормализации. В техническом анализе флаги паттернов отображаются на вкладке паттернов, а их дополнительные числовые и текстовые параметры — в таблице показателей.

### Выбор инструментов

Первая строка `TickerListManager` — кнопка редактирования списка, без поиска и тегов тикеров. Диалог при каждом открытии запрашивает `GET /investai/instruments` без параметров. `SignalInstrumentsHelper` оставляет записи с непустым `last_forecast_date`, нормализует и сортирует тикеры; `not_ready` с датой тоже доступен для выбора. Контракт сверяется с [OpenAPI InvestAI](https://apidev.alor.ru/investai/docs#/signals/get_instruments_investai_instruments_get).

Выбор редактируется локально и сохраняется одной операцией в прежний `TickersStateRecord` только по кнопке «Применить». Существующие доступные тикеры отмечены; недоступные не попадают в применённый список. Отмена и ошибка загрузки не меняют сохранённый список. Общий чекбокс выбирает все доступные инструменты или снимает все отметки; частичный выбор отображается промежуточным состоянием. Прежний UI-лимит в 10 тикеров снят, счётчик показывает число выбранных из общего числа доступных инструментов. Пустой выбор разрешён. Запрос отменяется при закрытии диалога или уничтожении компонента.

## Общие элементы

### Статусы API

Контракт `GET /investai/signals/latest` учитывает пример ответа `signal-2` от 04.09.2026: `signals` может содержать запись `status: "not_analyzed"` без `consensus`, дат и цены. Это не ошибка генерации: список показывает «Не анализировался», `status_note` доступен в подсказке, пустой диалог не открывается. Выбор инструмента по иконке сохраняется. Такой статус имеет приоритет перед случайно оставшимися данными консенсуса.

`ok` проверяется вместе с содержимым: отсутствие `consensus` означает ошибку, непустые `errors`/`warnings` при наличии консенсуса — ограниченный анализ. Старые ответы без `status` и неизвестные значения используют ту же проверку содержимого. Полностью отсутствующий тикер по-прежнему получает локальный статус `NoData`. Счётчики `meta.n_not_analyzed`/`meta.n_not_ready` не заменяют статус конкретного тикера; наличие счётчика не определяет полный набор значений `signals[].status`.

### Компоненты

- `SignalOverview` — общие направление, действие, ожидаемая прибыль со сроком и круговой confidence для списка, консенсуса и аналитиков. В списке действие скрыто.
- `SignalSection` — заголовок с панелью; `panel=false` используется, когда вложенный компонент уже имеет собственную панель.
- `TradePlanChart` — подробный или компактный торговый план. `TradePlanComparison` использует компактные графики с общей шкалой и таблицу точных значений.
- `TradePlanMarker` задаёт одинаковые цвета и размеры ценовых точек. В режиме легенды обводка не рисуется.
- `TradePlanViewHelper` централизует ценовые уровни, тултипы, шкалу и расчёт ожидаемой прибыли. Для единственной цены шкала расширяется; для отсутствующих цен выводится пустое состояние. Отношение прибыль/риск не участвует в ценовой шкале.
- Ожидаемая прибыль считается от цены входа до первой цели с учётом покупки/продажи. При неизвестном действии, неположительной прибыли или противоречащих направлению уровнях результат скрывается; исходные уровни остаются доступны для просмотра.
- `styles/analysis-shared.less` и `styles/analysis-table.less` содержат локальные mixin-ы оформления секций, таблиц, чисел и подсказок. Используются CSS variables терминала, без изменения глобальной темы.
- Общие подписи находятся в scope `ai-signals`, ценовые уровни — в `ai-signals/trade-plan-chart`; специфичные тексты — в scopes секций. Ключи поддерживаются синхронно для `ru`, `en`, `hy`.

## Проверки

Для логики нормализации сигналов, фундаментальных и технических показателей, видимости сводки и ценовой шкалы используются unit-тесты чистых helpers, для общей секции — тесты проекции содержимого. Тесты сервиса деталей проверяют обновление цены, отмену запросов и сохранение неизменившегося анализа. Сборка проверяется через consuming приложения согласно README библиотеки.

```sh
pnpm exec ng test terminal-widgets-lib --no-watch --include '**/ai-signals/**/*.spec.ts'
pnpm run build:all
pnpm test
pnpm lint
```
